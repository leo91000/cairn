# Bounded log coverage

`scripts/log-coverage.py` runs on the source host with Python 3.12+ and no third-party packages. It reads the supported Docker CLI or systemd journal interface, aggregates locally, and writes one small JSON object. It never returns source messages or command diagnostics. Keep deployment hosts, SSH authorities and monitor configuration outside this repository.

```sh
python3 scripts/log-coverage.py --request '{"kind":"docker","container":"example","since":"2026-10-31T10:00:00Z","until":"2026-10-31T10:01:00Z"}'
```

Journal reads select only timestamps, cursor and message fields and pass `--all`: otherwise journalctl JSON silently replaces fields larger than 4096 bytes with null. The local record limit still fails closed on oversized or unsupported records.

For systemd use `kind: "journal", unit: "example.service"`; use `kind: "kernel"` for the kernel journal. The caller needs read authority. This command neither changes logging configuration nor installs a service. For SSH, send the script on stdin to `python3 - --request …`. `scripts/log-coverage.mjs` supplies shell quoting and validates the counters/watermark contract for a JavaScript caller.

The helper selects oldest temporal pages, initially at most 70 seconds wide. Each attempt has a 512,000-byte work budget; an overfull page is retried at half its width. Reduced retry width is returned as `pageSpanNs` and persisted in the adapter state even when no page completed, so a fresh tick does not repeat an unaffordable initial page. Exhausting the final shared allowance does not shrink an otherwise fitting learned page. Cheap completed pages widen again while backlog remains, so a formerly overloaded source can catch up after its volume falls; a changed source starts with a fresh width. All widening remains under the same maximum page width and work/time/attempt limits. A collection has at most eight attempts, 2 MiB total source work, and ten seconds including identity checks. The work budget is local CPU/I/O work, not a larger raw-log transport allowance. Docker transport remains a counters-only JSON response, normally a few kilobytes. Journal callers can request a shorter time budget. Individual records are limited to 16 KiB and chunks to 16 KiB per pipe. Parsing buffers stay below two records plus chunks; neither messages nor page results accumulate in arrays.

Every credited page must reach pipe EOF, exit zero and have no parser or budget abandonment. Failed attempts receive no watermark credit; their positive counters remain in `partialCounts` and can repeat when the page is retried. `counts` describes completed pages within this invocation. `coveredThrough` is the end of the last contiguous completed page, never the tick time. `caughtUp` and `complete` concern the requested closed window of *available* records; a successful EOF cannot prove that older records were not already rotated away. A smaller source-clock cutoff can leave a backlog. `limits`, unsuccessful exit, unknown formatter counts and history continuity remain independent evidence.

Intervals are half-open `[since, until)` with nanosecond Docker timestamps or microsecond journal timestamps filtered locally. Boundary-equal records belong to the next page, including records sharing a timestamp. The upper bound cannot exceed source-host time minus two seconds. A monitor may request an older upper bound and overlap its previous cursor for late writes. Overlap and retry counters are conservative observations, not unique event totals. While a replay is incomplete, resume at the last completed page rather than subtracting the overlap again; otherwise pages narrower than the overlap can replay forever. Apply the overlap again after catch-up. The persisted continuity anchor is still verified on every invocation.

A retained anchor later than an early overlap page is pending verification, not missing. Keep it across pages/ticks until a completed page includes its timestamp; only then can absence indicate a gap. Retry reduction clamps at the minimum supported one-millisecond span. Identity recheck time is reserved inside the total budget.

Docker identity is its immutable container ID plus start epoch, checked before and after collection. Journal identity includes the selected unit/kernel and host boot epoch. Source changes invalidate continuity. An anchor contains only a Docker timestamp/stream or opaque journal cursor, never message content. Later reads include and verify that anchor; a missing anchor exposes lost or unknown retained history. Bootstrap continuity is explicitly unproven. These observations assume normal prefix rotation and cannot establish an audit-grade history, arbitrary external deletion, or correctness through clock rollback. Do not access Docker's private `json-file` storage.

The JavaScript adapter retains a historical gap until an operator explicitly acknowledges it **and** a caught-up read confirms the anchor. An old acknowledgement cannot clear a new source/anchor gap. It also withholds a healthy verdict while application records are unclassified. Persist the returned state and advance only to its actual `coveredThrough`, including when a completed old page leaves backlog. Persist gap evidence independently of the cursor; catching up available records alone does not resolve unknown history.

Validation: `python3 scripts/tests/log_coverage_test.py` exercises real subprocess pipes, fragmentation, boundaries, malformed/oversized records, time/byte budgets, severity, journal parsing and page watermarks. `pnpm exec vitest run scripts/tests/log-coverage*.test.mjs` runs that suite and the wire/state contract. Real-host qualification should compare only metrics on the same closed interval against a full untailed Docker/journal reference. Never save or transport the raw logs for that comparison.

References: [Docker logs](https://docs.docker.com/reference/cli/docker/container/logs/) defines batch retrieval, timestamps, since and until; [journalctl](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html) documents JSON field omission and `--all`; [json-file logging](https://docs.docker.com/engine/logging/drivers/json-file/) documents finite rotation and reserves its files for the daemon.
